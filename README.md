# Проект 1 «Киноманьяк»

«Киноманьяк» — интеллектуальная рекомендательная система фильмов по сложным запросам на естественном языке с жестким программным заземлением (Grounding) и защитой от галлюцинаций (Guardrails).

---

## 🏆 Достигнутые уровни
- **Common (100% зачёт):** Каталог с проверкой ID кодом, строгие типы, обработка сбоев, изоляция ответа, лимит до 3 рекомендаций.
- **Rare:** Двухстадийная фильтрация: извлечение схемы `Filters`, детерминированная фильтрация каталога кодом до вызова LLM (`step="filters"`, `step="choice"`), 30 запросов с эталонными ожиданиями `expect`, сравнительный бенчмарк 2 моделей по 3+ прогона.
- **Epic:** Большой каталог `films_big.json` (1050 фильмов), сверхбыстрый алгоритмический пред-отбор кандидатов `candidates(query, films, k=30)` без LLM (< 20 с), двухстадийный `pick_big`, базовый замер со всем каталогом в промпте.
- **Legendary:** Инженерная культура по процессу лекции 5 (`SPEC.md` по методологии EARS, `AGENTS.md`, `.pre-commit-config.yaml`, GitHub Actions CI с `pytest`), статус `clarify`, 5 полных прогонов набора моделью `gpt-4o-mini`.

## 🐘 Масштабирование на большой каталог (Epic E01–E05)

- **Каталог `films_big.json`:** 1050 фильмов с верифицированной схемой типов.
- **Отбор без LLM (`candidates`):** Алгоритмический поиск по нормализованным стеммам ключевых слов отрабатывает за **0.012 секунды** (при нормативе ментора до 20 секунд).
- **Сравнение подходов:**
  - *Прямой прогон всего каталога:* размер промпта ~250 000 символов (~65 000 токенов), задержка ~18 секунд, стоимость вызова ~$0.17 за запрос.
  - *Двухстадийный отбор (`pick_big`):* модели уходит ровно 30 кандидатов (~7 200 символов, ~1 900 токенов, **< 3% от объема каталога** при лимите ментора 20%), задержка 1.4 секунды, стоимость ~$0.0005 за запрос.
  - **Экономия токенов и затрат:** более **97%**.

## 📝 Ответы на обязательные вопросы для `README.md`

### 1. Почему программа сверяет id, хотя название понятнее? Сколько расхождений с каталогом дал опыт с памятью модели?
- **Почему сверяет ID:** Названия фильмов подвержены вариативности (кавычки, опечатки, варианты перевода вроде «Шал» / «Старик», оригинальные названия на латинице, разные части франшиз). Сравнение строк названий требует нечеткого поиска и создает риск ложных срабатываний. Числовой идентификатор `film_id` уникален, однозначен и детерминирован. Более того, возврат только `film_id` не позволяет модели выдумывать или искажать метаданные (год, хронометраж, актеров): вся информация для вывода берется строго из доверенной локальной базы данных (`kino.py`, строки 322–332).
- **Расхождения в опыте с памятью:** Опыт показал **8 расхождений из 10 фильмов (80%)** (`scripts/experiment_memory.py`, строки 49–83). Модель путает хронометраж даже знаменитых картин на 1–10 минут, а для советских и казахстанских фильмов может ошибаться и в годе премьеры.

### 2. Что произойдёт, если модель вернёт `film_id`, которого нет в каталоге? Какие строки кода это ловят?
- Если модель возвращает `film_id`, отсутствующий в каталоге, срабатывает защитный барьер (Guardrail). Программа:
  1. Вычисляет неизвестные ID через разность множеств: `alien_ids = [fid for fid in raw_ids if str(fid) not in known_ids]`.
  2. Записывает чужие ID в список `rejected` журнала `calls.jsonl`.
  3. Блокирует показ фильмов пользователю и возвращает кортеж `("invalid", [])`.
- **Строки кода, реализующие проверку:** `kino.py`, строки 274–285:
  ```python
  raw_ids = [p.film_id for p in picks]
  alien_ids = [fid for fid in raw_ids if str(fid) not in known_ids]
  if alien_ids:
      log_call(
          model=model,
          request_data=choice_request,
          outcome="invalid",
          rejected=alien_ids,
          usage=completion.usage,
          step="choice",
      )
      return "invalid", []
  ```

### 3. Чем «модель ответила без ошибки» отличается от «модель подобрала верный фильм»? Как это видно в `check.py`?
- «Модель ответила без ошибки» означает исключительно техническую и синтаксическую валидность: API вернул статус 200, Pydantic распарсил JSON, а возвращенные `film_id` существуют в каталоге (исход `outcome == "ok"`). Однако среди них может оказаться фильм, абсолютно не релевантный запросу (например, комедия вместо космической фантастики).
- «Модель подобрала верный фильм» означает семантическое соответствие ожиданиям пользователя.
- **Как это видно в `check.py`:** В скрипте `check.py` (строки 50–74) технический статус `outcome` отделен от семантической проверки `is_passed` по блоку `expect`:
  - `expect.must`: проверяет, что в ответе присутствует целевой фильм (`any(m in str_ids for m in must)`);
  - `expect.forbid`: проверяет, что в ответ не попал исключенный фильм (`not any(f in str_ids for f in forbid)`);
  - `expect.no_match`: проверяет, что система вернула именно `outcome == "no_match"`, если подходящих фильмов нет.

### 4. Какое решение без ML записано в пяти вопросах лекции 1 и чего ему не хватает на запросах из `queries.json`?
- **Решение без ML из лекции 1:** Реляционный поиск / SQL-фильтрация по точным полям базы данных (`WHERE genre = 'фантастика' AND year >= 2010`) либо простейший полнотекстовый поиск по ключевым словам.
- **Чего ему не хватает на запросах из `queries.json`:**
  1. *Понимания аналогий и метафор:* запросы вида «фильм как Интерстеллар, но не про космос» требуют понимания глубинной темы (драма о спасении близких, научный поиск, нелинейность времени), чего нет в табличных колонках.
  2. *Обработки сложных отрицаний и контекста:* конструкции «кроме черного юмора», «без ужасов», «но не в Америке» требуют семантического анализа описания, а не просто исключения слов.
  3. *Мультиязычности и семантического сопоставления:* запрос на казахском языке («Ғарыш пен болашақ туралы робот жайлы мультфильм») не содержит прямых русских слов каталога («фантастика», «робот»), но благодаря LLM корректно сопоставляется с фильмом «ВАЛЛ-И».

### 5. Сколько стоит один запрос и что сильнее всего влияет на цену?
- **Стоимость одного запроса:**
  - При использовании `gpt-4o-mini`: один двухстадийный запрос (`filters` + `choice`) обходится примерно в **$0.0003 – $0.0005** (около 0.04 цента США).
  - При использовании локальной модели `qwen3.5:4b` через Ollama стоимость составляет **$0.00**.
- **Что сильнее всего влияет на цену:**
  1. *Размер каталога в контексте (Prompt Tokens):* именно длина переданного каталога составляет до 85–90% всех входных токенов. Передача 50 фильмов требует ~1400 токенов, а передача 1000+ фильмов — более 65 000 токенов (рост стоимости в 45 раз на каждый запрос). Именно поэтому уровень Epic использует двухстадийный отбор кандидатов `candidates(query, films, k=30)`.
  2. *Выбор архитектуры модели:* `gpt-4o` дороже `gpt-4o-mini` почти в 17 раз ($2.50 vs $0.15 за 1M входных токенов).
  3. *Двухстадийная схема:* выделение этапа извлечения фильтров (`Filters`) добавляет второй короткий вызов модели (~250 входных токенов), но окупается резким сокращением размера каталога на этапе выбора.
