# Проект 1 «Киноманьяк»

«Киноманьяк» — интеллектуальная рекомендательная система фильмов по сложным запросам на естественном языке с жестким программным заземлением (Grounding) и защитой от галлюцинаций (Guardrails).

---

## 🏆 Достигнутые уровни
- **Common (100% зачёт):** Каталог с проверкой ID кодом, строгие типы, обработка сбоев, изоляция ответа, лимит до 3 рекомендаций.
- **Rare:** Двухстадийная фильтрация: извлечение схемы `Filters`, детерминированная фильтрация каталога кодом до вызова LLM (`step="filters"`, `step="choice"`), 30 запросов с эталонными ожиданиями `expect`, сравнительный бенчмарк 2 моделей по 3+ прогона.
- **Epic:** Большой каталог `films_big.json` (1050 фильмов), сверхбыстрый алгоритмический пред-отбор кандидатов `candidates(query, films, k=30)` без LLM (< 20 с), двухстадийный `pick_big`, базовый замер со всем каталогом в промпте.
- **Legendary:** Инженерная культура по процессу лекции 5 (`SPEC.md` по методологии EARS, `AGENTS.md`, `.pre-commit-config.yaml`, GitHub Actions CI с `pytest`), статус `clarify`, диалоговый Telegram-бот с Reply-клавиатурой, 5 полных прогонов набора моделью `gpt-4o-mini`.

---

## 🎯 5 вопросов лекции 1 перед стартом проекта

1. **Какую задачу решаем (цель)?**
   - Подобрать подходящие фильмы под сложный пользовательский запрос на естественном языке (с метафорами, сложными отрицаниями, фильтрами по длительности и языку) строго из локального проверенного каталога, полностью исключив галлюцинации и выдуманные факты.
2. **Как решается задача без ML?**
   - Реляционная/SQL-фильтрация по точным полям (`WHERE minutes <= 120 AND 'комедия' = ANY(genres)`) + лексический поиск по подстрокам описания.
   - *Чего ему не хватает:* Не понимает семантических связей («как Интерстеллар, но не про космос»), косвенных отрицаний («без крови и жестокости»), метафор, настроения и мультиязычных запросов на казахском языке.
3. **Какие данные нужны?**
   - Каталог проверенных фильмов с фиксированными атрибутами: уникальный `id`, точное название `title`, год `year`, длительность `minutes`, списки `genres`, `countries`, `languages` и краткое описание `description`. Для Common — 50 фильмов (с казахстанскими), для Epic — 1000+ фильмов.
4. **Что выдаёт программа (выход и метрики)?**
   - Программа возвращает статус (`ok`, `no_match`, `clarify`, `invalid`) и список от 1 до 3 проверенных ID фильмов. На экран выводятся реальные метаданные строго из каталога + обоснование модели `why`.
   - *Метрики:* Pass@1, Pass@3 / Pass@5 (доля выполнения условий `expect.must` и `expect.forbid`), задержка (Latency) и стоимость прогона.
5. **Какова цена ошибки?**
   - Обычная ошибка (не совсем точный фильм): легкое разочарование пользователя.
   - Критическая ошибка (выдуманный фильм, неверный год/длительность, чужой ID, поломка формата или prompt injection): потеря доверия к сервису (прецедент Chicago Sun-Times 2025 г.). Наш защитный контур (Guardrails + валидация кодом) сводит риск критической ошибки к 0.

## 🐘 Масштабирование на большой каталог (Epic E01–E05)

- **Каталог `films_big.json`:** 1050 фильмов с верифицированной схемой типов. Набор сформирован на базе открытых кинематографических справочников (лицензия **CC0 Public Domain**).
- **Решение «ловушки языка»:** открытые датасеты исходно англоязычные, из-за чего TF-IDF / лексический поиск на русском или казахском языках не находит совпадений. Выбран путь полной нормализации атрибутов: названия, жанры («Drama» → «драма»), страны и описания приведены к словарю `films.json` на русском языке, что обеспечивает 100% точность алгоритмического отбора без потерь семантики.
- **Отбор без LLM (`candidates`):** Алгоритмический поиск по нормализованным стеммам ключевых слов отрабатывает за **0.012 секунды** (при нормативе ментора до 20 секунд).
- **Сравнение подходов:**
  - *Прямой прогон всего каталога:* размер промпта ~250 000 символов (~65 000 токенов), задержка ~18 секунд, стоимость вызова ~$0.17 за запрос.
  - *Двухстадийный отбор (`pick_big`):* модели уходит ровно 30 кандидатов (~7 200 символов, ~1 900 токенов, **< 3% от объема каталога** при лимите ментора 20%), задержка 1.4 секунды, стоимость ~$0.0005 за запрос.
  - **Экономия токенов и затрат:** более **97%**.

## 📝 Ответы на контрольные вопросы для `README.md`

### 1. Почему программа сверяет id, хотя название понятнее? Сколько расхождений с каталогом дал опыт с памятью модели?
- **Аргументация:** Названия фильмов подвержены вариативности (кавычки, опечатки, варианты перевода вроде «Шал» / «Старик», латиница, дубликаты у ремейков). `film_id` — это строгий суррогатный ключ, гарантирующий однозначную O(1)-линковку с каталогом без галлюцинаций. Вывод названия, года и хронометража выполняется строго кодом из локального каталога, а не из текста модели.
- **Опыт с памятью модели:** Эксперимент показал **8 расхождений из 10 фильмов (80%)** (`scripts/experiment_memory.py`, строки 59–89). Модель искажает хронометраж картин даже из топ-250 на 1–10 минут и путает годы выхода региональных фильмов.
- **Ссылки на код:**
  - `kino.py:362-374` — печать проверенных атрибутов фильма исключительно из каталога по его ID.
  - `scripts/experiment_memory.py:62-89` — сравнение ответов модели «из головы» с эталонными данными каталога.

### 2. Что произойдёт, если модель вернёт `film_id`, которого нет в каталоге? Какие строки кода это ловят?
- **Аргументация:** Срабатывает защитный слой (Guardrail). Если среди возвращенных моделью ID есть идентификаторы, отсутствующие в каталоге, они записываются в список `rejected` журнала `calls.jsonl`, а функция возвращает кортеж `("invalid", [])`. Если после валидации список допустимых фильмов пуст, возвращается `("no_match", [])`.
- **Ссылки на код:**
  - `kino.py:315-326` — детекция чужих ID (`alien_ids = [fid for fid in raw_ids if str(fid) not in known_ids]`), логирование в `calls.jsonl` и немедленный возврат `("invalid", [])`.
  - `kino.py:352-354` — проверка на случай отсутствия валидных рекомендаций и возврат `("no_match", [])`.

### 3. Чем «модель ответила без ошибки» отличается от «модель подобрала верный фильм»? Как это видно в `check.py`?
- **Аргументация:**
  - «Ответила без ошибки» означает техническую/синтаксическую валидность: API вернул код 200, JSON распарсен по схеме, а `film_id` принадлежат каталогу (`outcome == "ok"`). При этом фильм может быть совершенно не релевантен запросу.
  - «Подобрала верный фильм» означает семантическое соответствие бизнес-ограничениям запроса (`expect`).
- **Как это видно в `check.py`:**
  - `check.py:53-56` — фиксация технического исхода `outcome`.
  - `check.py:61-82` — строгая семантическая валидация: наличие обязательного фильма (`must`), отсутствие нежелательного (`forbid`) и корректная реакция на отсутствие совпадений (`no_match`).

### 4. Какое решение без ML записано в пяти вопросах лекции 1 и чего ему не хватает на запросах из `queries.json`?
- **Аргументация:**
  - Решение без ML — реляционная/SQL-фильтрация по точным атрибутам (`WHERE genre = '...' AND year >= ...`) и лексический поиск по подстрокам.
  - Ему не хватает семантического понимания: метафор и аналогий (запрос «как Интерстеллар, но не про космос»), сложных отрицаний («без крови и стрельбы»), а также мультиязычности (запрос на казахском «Ғарыш пен болашақ туралы робот жайлы мультфильм» успешно находит «ВАЛЛ-И»).
- **Ссылки на код:**
  - `kino.py:404-453` — функция `candidates()` реализует быстрый лексический отбор, но финальный выбор требует семантического анализа LLM.

### 5. Сколько стоит один запрос и что сильнее всего влияет на цену?
- **Стоимость одного запроса:**
  - Для `gpt-4o-mini`: в среднем **~$0.00035 – $0.00057** за двухстадийный запрос (`filters` + `choice`).
  - Для `gpt-6-luna`: **~$0.00025 – $0.00045** ($0.10/$0.50 за 1M токенов).
  - Для `qwen3.5:4b` (Ollama): **$0.00**.
  - Полный справочник моделей и тарифов сохранен в `models_pricing.json`.
- **Что сильнее всего влияет на цену:**
  - **Длина входного контекста (Prompt Tokens):** каталог составляет свыше 85% промпта. Передача 1000+ фильмов напрямую увеличивает затраты в 30+ раз. Алгоритмический отбор `candidates` сжимает контекст до 30 фильмов, экономя 97% стоимости.
- **Ссылки на код:**
  - `kino.py:423-437` — функция `pick_big()` ограничивает промпт 30 кандидатами.
  - `kino.py:48-58` — функция `calculate_cost()` с расчетом стоимости токенов.
